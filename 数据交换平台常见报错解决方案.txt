问题：Could not resolve column/field reference: 'part_num’
原因 / 处理：源表无part_num，目标表有part_num，将part_num设置为分区字段，加载字段取消选择part_num。接下来会报下面一个错误


问题：ERROR processing query/statement. Error Code: 0, SQL state: TStatus(statusCode:ERROR_STATUS, sqlState:HY000, errorMessage:AnalysisException: Target table 'dmcrdm_data.t01_corp_basic_info_c' has more columns (96) than the SELECT / VALUES clause and PARTITION clause return (95)

原因 / 处理：源表无分区字段，目标表有分区字段，字段无法一一对应。下面两种方法都可解决：
(1)修改后置SQL为：insert overwrite table 【table_name1】 partition(part_num) select 【columns】, cast(regexp_replace(substr(etl_dt,1,10),'-','') from 【table_name2】。手动为part_num赋值。

(2)改库对库为抽取入库，目标表多出来的字段赋常量。（只有库对库的字段映射是根据源字段来的，其余都是根据目标字段）


问题：分区字段与数据日期同步方法
原因 / 处理：后置sql的分区字段`part_num`改为cast(regexp_replace(substr(etl_dt,1,10),'-','') as varchar(30))

界面报错
问题：查看或编辑作业，界面报错：“查询装数定义[id]异常，详情见后台日志信息”

原因 / 处理：
1）（系统管理员操作）本地调试。
本地环境新建同一个订阅作业：
订阅表：dl_load_define
发布清单：BDIP_PUB_FILE_INFO
发布表：de_query_define
关联关系：dld.pub_file_info_id = bpfi.id、dqd.id = bpfi.job_id
单步调试问题定位到meta_table表版本与dl_load_define.table_id不匹配
2）查看元数据同步记录。
目标表(版本2)被删除，元数据同步后会将该表之前所有版本都删除，后来重新建表、重新同步，该表版本号为1。应新建作业，重新选择目标表(版本1)。

数据开发（模板化开发）

存量脚本可先转成mapping格式，根据开发规范和Mapping填写规范补充别名、注释、字段类型等信息。

创建需求
登陆数据开发平台UAT环境（159.1.38.109:8000/#/login），选择租户，并创建需求

获取生产脚本
在开发平台下载最新脚本

脚本解析
数据开发平台：数据开发-数据加工-脚本解析，导入原脚本生成数据映射。映射与原脚本比对，逐行比对是否一致

拖拽SQL文件即会生成Mapping文件，注意EXCEL第一个sheet页《sqlCheckMessage》里会打印出不符合规范的内容

补全数据映射
index页的算法标识（例如SN_F，根据实际情况填写）和保留周期（例如13，根据实际情况填写）、字段类型、表别名等

生成脚本
数据开发平台：从数据开发卡片导入数据映射生成新脚本


验证准备
数据开发平台：数据开发-作业列表-搜索对应脚本名并下载新脚本。变更脚本名：添加后缀xxx_kfpt.sql，并修改新脚本内容：schema.tablename整体替换为schema.tablename_kfpt

执行验证
上传新脚本至UAT服务器（159.1.44.61）
备份原脚本以及原表数据，新建表（create table xxx.xxx_kfpt as select * from xxx.xxx;）并赋权给labdata

端到端数据验证
新脚本跑批，跑批结果与原脚本跑批结果进行比对，核对数据量以及数据是否完全一致

问题反馈
如发现Mapping内容不对、生成的新脚本不对等情况则在开发平台【问题收集】上提交文字和截图，并在群里反馈

同时开发平台也会保留一份导入的EXCEL，可通过【数据开发】---【作业列表】中选择对应的脚本的图标线上查看Mapping内容。
