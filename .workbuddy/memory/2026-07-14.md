# 2026-07-14 离线部署包制作

为「报错处理知识库」(Vue2.6 + Spring Boot 2.7.18 + H2) 制作 Linux x86_64 离线部署包，不含 Docker。

## 成品
- 目录: 报错处理知识库-离线部署包-Linux-x86_64/（含 jre/、error-knowledge-base-1.0.0-SNAPSHOT.jar、deploy.sh、stop.sh、README_部署.md）
- 压缩包: 报错处理知识库-离线部署包-Linux-x86_64.tar.gz（74MB）

## 关键做法
1. 前端: node 22 + `NODE_OPTIONS=--openssl-legacy-provider npm run build`（Vue2+webpack5 在 Node17+ 需此兼容），产物 dist 复制到 backend/src/main/resources/static，由后端同源托管 `/`（前端用 hash 路由、`/api` 相对路径，无需代理）。
2. 后端: 用本机 Zulu JDK 8（/Library/Java/JavaVirtualMachines/zulu-8.jdk）配 JAVA_HOME 编译 `mvn -DskipTests clean package`，避免系统 JDK 26 导致 Lombok 失败。
3. JRE: 内置 Zulu JRE 8 (linux x64)。**不要用 Adoptium API（api.adoptium.net 重定向到 GitHub/Azure，本沙箱被限流到 ~400B/s）**；改用 Azul CDN `https://cdn.azul.com/zulu/bin/zulu8.94.0.17-ca-jre8.0.492-linux_x64.tar.gz`（~9MB/s）。注意后台任务(Bash run_in_background)的 /tmp 与前台不共享，下载产物要在前台可见路径或用前台下载。
4. deploy.sh: cd 到脚本目录→优先用 ./jre/bin/java→健康检查 curl /api/error-record/categories→PID 文件管理；数据/上传目录相对 CWD（./data、./uploads），故必须 cd 到部署目录启动。

## 验证
- 本机用 Zulu JDK 8 启动 jar 冒烟测试通过：首页、/api 搜索、H2 初始化(54条) 正常。
- JRE 经 `file` 确认为 Linux x86-64 ELF。
