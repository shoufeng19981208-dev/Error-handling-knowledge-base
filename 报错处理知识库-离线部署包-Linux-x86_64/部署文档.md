# 报错处理知识库 · 离线部署文档（Linux x86_64）

> 本部署包完全自包含：内置 Zulu JRE 8（Linux x86_64 glibc）与全部依赖，
> 目标服务器**无需联网、无需安装 Java / Maven / Node / Docker**。

## 一、包内容

```
报错处理知识库-离线部署包-Linux-x86_64/
├── error-knowledge-base-1.0.0-SNAPSHOT.jar   # 应用（前端页面已打包在内，单端口提供全部服务）
├── jre/                                       # 内置 Zulu OpenJDK 8 JRE（Linux x86_64 glibc）
├── deploy.sh                                  # 一键部署（首次/升级都执行它）
├── start.sh / stop.sh / restart.sh / status.sh  # 一键启停与状态
├── env.sh                                     # 脚本公共定义（无需直接执行）
├── config/application.yml                     # 外置配置（端口等，改后 ./restart.sh 生效）
├── data/                                      # H2 数据库文件（自动生成，备份重点）
├── uploads/                                   # 报错截图（备份重点）
├── logs/                                      # 运行日志 app.log
├── 报错处理知识库-收集模板.xlsx                 # 线下收集模板（页面里也可下载）
└── 部署文档.md                                 # 本文档
```

## 二、环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux x86_64（glibc，内核 2.6.18+，常见 CentOS 6/7/8、RHEL、麒麟、统信等均可） |
| 网络 | 无需外网；使用方能访问服务器的 8080 端口（或自定义端口）即可 |
| 磁盘 | ≥ 500MB（含运行数据余量） |
| 内存 | ≥ 1GB 可用（JVM 默认 -Xms256m -Xmx1024m） |
| 依赖软件 | 无（Java 已内置；脚本仅用 bash 基础能力，不依赖 curl/wget） |

## 三、一键部署（3 步）

```bash
# 1. 上传 tar.gz 到服务器任意目录（如 /opt），解压
tar xzf 报错处理知识库-离线部署包-Linux-x86_64-*.tar.gz
cd 报错处理知识库-离线部署包-Linux-x86_64

# 2. 一键部署（自动初始化目录 → 启动 → 等待就绪）
./deploy.sh

# 3. 浏览器访问（IP 换成服务器地址）
#    http://<服务器IP>:8080
```

- 首次启动会自动建库并初始化 **54 条**内置报错记录（TO层报错 + 数据交换平台）。
- 若提示 `Permission denied`，先执行 `chmod +x *.sh` 再运行。

## 四、日常运维

| 操作 | 命令 |
|------|------|
| 启动 | `./start.sh` |
| 停止 | `./stop.sh` |
| 重启 | `./restart.sh` |
| 查看状态 | `./status.sh`（PID、端口、运行时长、内存） |
| 看日志 | `tail -f logs/app.log` |
| 健康检查 | 访问 `http://<IP>:<端口>/api/error-record/categories` 返回 JSON 即正常 |

## 五、修改端口 / 配置

编辑 `config/application.yml`（属性级覆盖 jar 内默认配置），改完执行 `./restart.sh`：

```yaml
server:
  port: 9090        # 改成需要的端口
```

内存调整：启动前设置环境变量，例如 `JAVA_OPTS="-Xms512m -Xmx2048m" ./restart.sh`。

## 六、数据备份与升级

**数据只存在两个目录**（均在部署包根目录下，随时可整体拷贝备份）：

- `data/` —— H2 数据库文件（全部报错记录）
- `uploads/` —— 报错截图文件

**备份**：`tar czf kb-backup-$(date +%F).tar.gz data uploads`

**升级到新版本**（数据保留）：

```bash
./stop.sh
# 用新包中的 jar 覆盖旧 jar（data/、uploads/、config/ 不动）
cp /path/to/新包/error-knowledge-base-*.jar .
./start.sh
```

也可以直接在新解压的包目录里拷入旧的 `data/`、`uploads/` 后 `./deploy.sh`。
数据初始化只在**空库**时执行，已有数据不会被覆盖或重复插入。

## 七、功能速览（部署后即用）

- **智能日志匹配**：首页大输入框，整段报错日志 Ctrl+V 粘贴即自动匹配解决方案（无需自己提炼关键词）；未命中可一键登记为「待处理」。
- **批量导入**：首页「批量导入」→ 下载 xlsx 收集模板 → 线下按行收集 → 上传导入（示例行/重复标题自动跳过，逐行报告结果）。
- **录入辅助**：新增记录页「从报错内容提取」自动生成特征关键字。
- H2 控制台（排障用）：`http://<IP>:<端口>/h2-console`，JDBC URL `jdbc:h2:file:./data/errorkb`，用户名 `sa`，密码空。生产可在 `config/application.yml` 中关闭。

## 八、常见问题

| 现象 | 处理 |
|------|------|
| 端口被占用（日志有 `Address already in use`） | 改 `config/application.yml` 端口后 `./restart.sh`，或释放占用端口 |
| 页面打不开但 `status.sh` 显示运行中 | 检查服务器防火墙是否放行端口：`firewall-cmd --add-port=8080/tcp --permanent && firewall-cmd --reload`（或 iptables 相应放行） |
| `./deploy.sh` 提示权限不足 | `chmod +x *.sh jre/bin/*` 后重试 |
| 内置 JRE 无法运行（极少数非 glibc 系统） | 脚本会自动回退系统 `java`（需 Java 8+）；若系统也无 Java，需更换 glibc 服务器 |
| 上传截图报错 | 确认 `uploads/` 目录存在且启动用户有写权限 |
| 忘记数据在哪 | 全部在 `data/` 与 `uploads/`，见「六、数据备份与升级」 |

## 九、开机自启（可选，systemd）

创建 `/etc/systemd/system/errorkb.service`（路径按实际部署位置修改）：

```ini
[Unit]
Description=Error Knowledge Base
After=network.target

[Service]
Type=forking
WorkingDirectory=/opt/报错处理知识库-离线部署包-Linux-x86_64
ExecStart=/opt/报错处理知识库-离线部署包-Linux-x86_64/start.sh
ExecStop=/opt/报错处理知识库-离线部署包-Linux-x86_64/stop.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now errorkb
```
